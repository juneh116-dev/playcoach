# 가입자 관리 Google 스프레드시트

DB가 회원 정보의 원본이며, 운영자 전용 시트는 5분마다 갱신하는 관리용 사본입니다. 회원 ID·이름·이메일·가입일(한국시간)·가입 방식만 전송합니다. 소셜 제공자 이메일과 가입일이 저장되지 않은 과거 계정은 빈칸으로 표시하며 추정하지 않습니다. 마케팅 수신 동의나 연락처는 수집된 것으로 취급하지 않습니다.

## 최초 연결

1. 비공개 Google Sheet에 `가입자` 탭과 `회원 ID / 이름 / 이메일 / 가입일 (한국시간) / 가입 방식` 헤더를 A1:E1에 만듭니다. 헤더 행을 고정하고 필터를 설정합니다.
2. 서버 환경변수 `MEMBERS_SHEET_EXPORT_TOKEN`에 32자 이상의 충분히 무작위인 전용 비밀키를 설정하고 재배포합니다. 비밀번호·세션 토큰이나 DB 연결값을 재사용하지 않습니다.
3. 시트의 **확장 프로그램 → Apps Script**에서 `Code.gs`를 붙여 넣고 두 자리표시자를 해당 시트 ID와 위 전용 키로 바꿉니다. 키를 공개 저장소나 채팅에 올리지 않습니다.
4. 시트 소유자 계정으로 `setupMemberSync`를 한 번 실행하고 Google의 시트 접근·외부 요청·예약 실행 권한을 승인합니다. 먼저 전체 동기화가 성공한 다음 5분 간격 트리거를 설치합니다. **웹 앱 배포나 시트 공개는 필요하지 않습니다.**

현재 채팅의 Google 커넥터 인증은 Vercel 서버나 Apps Script에 자동 이전되지 않습니다. 초기 시트 작성 및 기존 가입자 복사와 주기적 자동 연결의 활성화 여부는 별도로 확인해야 합니다. 자동 연결 후 A1 메모에 마지막 성공 시각과 인원수가 표시됩니다. 초기 실행이 실패하면 트리거를 설치하지 않으며 원인을 수정하고 다시 실행합니다.

## 처리 방식

- `/api/internal/members-export`는 전용 Bearer 키가 맞는 경우만 500명 단위로 조회합니다. 브라우저 회원 로그인이나 공개 URL만으로 접근할 수 없습니다. 응답은 캐시하지 않습니다.
- 키 없는 상태는 503, 잘못된 키는 401입니다. 비밀키가 없는 시트는 연결 준비 상태입니다. DB 조회는 인증 성공 뒤에만 실행합니다.
- Apps Script는 전체 페이지를 가져온 뒤 시트를 갱신합니다. 실패한 페이지가 있으면 기존 값은 유지합니다. 스크립트 잠금과 회원 ID 중복 제거로 동시 실행·중복 기록을 방지합니다.
- DB에서 삭제된 계정은 다음 성공한 전체 동기화 때 시트에서도 사라집니다. `가입자!A:E`는 자동 관리 영역이므로 직접 메모를 덧붙이거나 수동 정렬하지 말고 별도 탭을 사용합니다.
- 이름·이메일이 `=`, `+`, `-`, `@`로 시작하는 경우 일반 텍스트로 기록해 수식 실행을 차단합니다. 개인정보와 키는 로그에 남기지 않습니다.
- 최대 100페이지(50,000명)이며 이를 초과하면 기존 시트를 덮어쓰지 않고 중단합니다. Google 실행 시간·호출 한도와 가입자 규모에 맞게 추후 배치 방식을 확장합니다.

## 중지·키 교체

Apps Script의 `syncPlaycoachMembers` 시간 트리거를 삭제하면 자동 갱신이 멈춥니다. Vercel의 전용 키를 교체하고 재배포하면 이전 키는 거부됩니다. 교체 시 Apps Script 속성의 `MEMBERS_EXPORT_TOKEN`도 갱신합니다. 시트는 소유자와 필요한 운영자에게만 제한 공유하고 링크 공개는 사용하지 않습니다. 공유·복사본의 보관과 삭제는 운영자가 관리해야 합니다.
